# 2026.261.0809 — feat: derive JETKVM_HOST + JETKVM_AUTH_TOKEN from the ssh connection

## Summary of changes

Adds a `charly-jetkvm env` subcommand so the **entire JetKVM check flow works from the initial ssh connection alone** — no committed hostname, no hand-copied token.

- `charly-jetkvm env --host <ssh-target> [--export] [--device-host <name>]`: reads the device's `local_auth_token` from `/userdata/kvm_config.json` **over ssh** and prints the two variables the `jetkvm:` verb consumes — `JETKVM_HOST` and `JETKVM_AUTH_TOKEN`. `--export` yields `eval`-safe lines; `--device-host` overrides the printed host when the ssh target and the reachable device name differ (default: the ssh target's host part).
- `tests/run-container-bed.sh`: the throwaway sshd container now also ships a `/userdata/kvm_config.json`, and the bed verifies `env` (default host, token read, `--export` eval-safety, `--device-host` override).
- `README.md`: documents the env flow, the two `env` flags, and `CHARLY_JETKVM_CONFIG`.

The token is only ever **printed** to stdout by this tool; it never writes it to a file. The device address resolves in the verb as authored `host:` → `JETKVM_HOST` → deploy venue (plugin side), so a plan can author no device address and stay portable.

**Closes / relates to:** `opencharly/plugin-jetkvm#5` (adds `JETKVM_HOST` on the plugin side and removes a committed hostname).

**Breaking change + rollback:** `none` — a new subcommand plus bed/README additions. Revert the merge to roll back.
