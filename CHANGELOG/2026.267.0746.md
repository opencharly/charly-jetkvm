# 2026.267.0746 — feat(auth): mint a missing local_auth_token over ssh, never overwriting existing auth

## Summary

Repairs a JetKVM whose `local_auth_token` is empty. Upstream JetKVM mints
`LocalAuthToken` **only** inside a successful login/setup handler
(`config.LocalAuthToken = uuid.New(); SaveConfig()`, `jetkvm/kvm` `web.go`) and
**never** re-mints it at startup (`LoadConfig` runs once, `config.go`). So a
device in `password` mode whose token was cleared — a logout, a config reset, a
crash before save — answers **HTTP 401** to every authenticated request, and the
`jetkvm:` plugin then falls to the password path and 401s there too when the
password is unknown. There was no recovery surface.

This adds one, over the ssh connection:

- `charly-jetkvm auth --host <target> [--print]` — ensure/repair the token.
- `charly-jetkvm env --host <target> --heal` — repair, then print the environment.
- helpers `read_local_token`, `read_auth_mode`, `app_present`.

It also fixes a latent bug it depended on: `rsh()` ended with an `IFS=$_oldifs`
assignment, which became the function's last command and **forced rc=0** — every
caller saw success even when ssh (or the remote command) failed. The readiness
poll is what exposed it; the fix preserves ssh's real exit status.

And it draws the line the base did not: a **failed config read** (unreachable
host, non-JetKVM host, unreadable path) is not a tokenless device.
`require_device_config` (`test -r $CONFIG_PATH`) runs FIRST in both `env` and
`auth`, so those cases die with a diagnostic instead of printing an empty token.

### The prime directive: add only what is missing, never reset existing auth

- a **non-empty** token is returned **untouched** — an existing live session is
  never invalidated;
- a device in **`noPassword`** mode legitimately has an empty token and is
  **never** minted into (that would silently start requiring auth);
- **only `password` mode with an empty token** is healed.

The repair writes a fresh uuid into `local_auth_token`, restarts `jetkvm_app`
(`killall`, wait for the old pid to be gone, `setsid … LD_LIBRARY_PATH=…
/userdata/jetkvm/bin/jetkvm_app`, wait for a NEW pid — the restart shape
upstream's own e2e helper `ui/e2e/helpers/ssh.ts:restartAppViaSSH` uses, made
race-free), then bounds both waits. The app loads the config ONCE at start, so a
restart is required for a written token to take effect.

### The `env` before/after (corrected — this is the real delta)

- **base:** `env` `die`d on **any** empty token (`[ -n "$token" ] || die …`),
  including a legitimate `noPassword` device — so it could not print the empty
  environment such a device actually needs.
- **now:** `noPassword` + empty ⇒ prints `JETKVM_AUTH_TOKEN=` (legitimate);
  `password` + empty + no `--heal` ⇒ dies with a message naming the `--heal`
  remedy; `password` + empty + `--heal` ⇒ mints, then prints a non-empty token;
  **failed config read** (unreachable / non-JetKVM / unreadable) ⇒ dies in both
  `env` and `auth` — it is never mistaken for a tokenless device.

The new assertions are the point — every new `env` branch and `auth` branch has a
step that would fail without it: a non-empty token returned unchanged;
password+empty minted-and-written with the app coming back; noPassword+empty
**not** minted; `env` without `--heal` failing loudly with the remedy; `env
--heal` minting and then a plain `env` succeeding.

### Live proof on the real device

The appliance (`jk.armadillo-quail.ts.net`) was in `password` mode with
`local_auth_token: ""` — the exact broken state:

```
$ charly-jetkvm auth --host root@jk.armadillo-quail.ts.net --print
password-mode device has no local_auth_token; minting one (existing auth is never overwritten)
restarting jetkvm_app so it loads the minted token (killall + respawn, upstream's own recovery shape)
dc898404-e7e6-46fb-9fba-a6a0aa650b3e

$ curl -sk -H "Cookie: authToken=dc898404-…" https://jk.armadillo-quail.ts.net/device
HTTP/2 200                      # was HTTP/2 401 before the fix

$ charly-jetkvm auth --host … --print      # second run
dc898404-e7e6-46fb-9fba-a6a0aa650b3e       # SAME token — never overwritten
```
